# حالة الإنجاز

## متطلبات الاختبار المنجزة

- استخدام CodeIgniter 3 وPHP وMySQL وHTML/CSS وJavaScript وAJAX.
- عرض المنتجات والبحث بالاسم أو الكود وفلترة التصنيف وPagination.
- إضافة المنتجات وتعديلها وتعطيلها.
- دعم عدة مستودعات وربط كل منتج بكمية داخل المستودع.
- عرض المخزون حسب المستودع.
- اختيار العميل والمستودع عند إنشاء الفاتورة.
- البحث عن المنتجات وإضافتها للفاتورة وتعديل الكمية وحذف البنود.
- تحديث إجماليات الفاتورة مباشرة في الواجهة.
- حفظ الفاتورة وبنودها في قاعدة البيانات.
- رفض البيع عند عدم كفاية المخزون.
- خصم بنسبة مئوية مع التقريب الصحيح.
- تقرير المنتجات عند حد التنبيه أو دونه، مع فلتر المستودع والبحث بالاسم أو الكود وعرض مقدار النقص.
- تصدير جميع نتائج التقرير المطابقة للبحث والمستودع إلى CSV، مع عناوين عربية وإنجليزية حسب لغة الواجهة.
- صلاحيات Admin لجميع المستودعات، ومستخدم المستودع لمستودعه فقط.
- معالجة تعارض البيع المتزامن باستخدام Transaction وSELECT FOR UPDATE.
- قائمة فواتير وصفحة تفاصيل لكل فاتورة.
- ملف SQL وتعليمات تشغيل وحسابات تجربة وسجل متعدد من commits على Git.

## إضافات المشروع

- إدارة التصنيفات والعملاء والمستودعات والمستخدمين وحالات التفعيل.
- إضافة عميل من شاشة الفاتورة والعودة إليه مباشرة.
- لوحة تحكم بإحصاءات المخزون والمبيعات والفواتير وتنبيهات النقص.
- تعديل الملف الشخصي وكلمة المرور واللغة، وإعدادات الشركة وبادئة الفواتير.
- دعم العربية والإنجليزية وRTL وLTR وتصميم متجاوب وقائمة جانبية للجوال.
- جداول AJAX ببحث وترقيم صفحات، وقوائم اختيار قابلة للبحث.
- فلترة المخزون بالمستودع والمنتج ونطاق الكمية، وعرض مقدار النقص عن حد التنبيه.
- عرض مخزون المستودعات غير النشطة للمدير دون السماح بتعديله.
- إضافة المخزون وسحبه وتعيين الرصيد النهائي مع سجل التعديلات والأسباب.
- إضافة منتج موجود إلى مستودع آخر، وإنشاء المنتج ومخزونه الابتدائي داخل Transaction.
- إخفاء المخزون الابتدائي عند عدم اختيار مستودع في نموذج المنتج.
- تعطيل اختيار منتج تعديل المخزون حتى تحديد المستودع، وفلترة المنتجات حسبه.
- تضمين المنتجات غير الموجودة في المستودع اختياريًا عند إضافة المخزون.
- إلزام اختيار العميل ومنع تكرار المنتج في واجهة الفاتورة.
- عرض سعر الوحدة والمخزون المتاح والمتبقي وحدود الكمية.
- عرض خصم البند والمبالغ قبل الخصم وبعده وملخص الفاتورة مباشرة.
- تقييد الكمية بحد أدنى 1 والخصم بين 0 و100% في الفاتورة.
- إعادة حساب الأسعار والإجماليات والتحقق من المخزون على الخادم.
- حفظ نسخة من بيانات المنتج والسعر داخل بنود الفاتورة.
- ترقيم يومي فريد للفواتير دون جدول عدّاد مستقل.
- عرض اسم منشئ الفاتورة، والطباعة، والإلغاء مع استعادة المخزون.
- تخزين أكواد الوحدات وترجمة أسمائها، وعرض SAR بالعربية مع فاصل عشري بالنقطة.
- الاحتفاظ بمدخلات نماذج المنتجات والمستخدمين وتعديل المخزون عند الأخطاء.
- رسائل تحقق مرئية وربط الأخطاء بالحقول والقوائم القابلة للبحث.
- جلسات تنتهي بعد 120 دقيقة من عدم النشاط وRemember me حتى 30 يومًا.
- تخزين كلمات المرور باستخدام Hash، وتحديد محاولات الدخول، وحماية CSRF وترميز المخرجات.
- تحديث صلاحيات الجلسة وإبطال الدخول المحفوظ عند التغييرات الأمنية.
- فصل العمليات الأساسية إلى Controller وService وRepository.
- Migrations وSeeder قابل لإعادة التشغيل دون تكرار البيانات التجريبية.
- اختبارات Unit وJavaScript وIntegration، و25 فحصًا عبر Playwright على قاعدة مؤقتة.
